## Fork Features

This fork extends the original GeminiForJanitors with native reasoning controls and thought display for Gemini 3 models.

### Gemini 3 Thinking Controls

- **Thinking level selection:** Supports JanitorAI's reasoning settings: Minimal, Low, Medium, and High, depending on model capabilities.
- **Model Default:** Leaves the thinking level unset, allowing Gemini to use its default configuration.
- **Model-specific compatibility:** Automatically handles differences in supported thinking levels between Gemini models.

### Native Gemini Thought Display

- **Real Gemini thoughts:** Uses Google's `includeThoughts` API option to retrieve thought summaries generated by Gemini.
- **JanitorAI integration:** Thought summaries are wrapped in standard `<think>...</think>` tags and displayed through JanitorAI's built-in Thoughts toggle.
- **Independent of legacy `//think`:** Native thoughts do not rely on prompt-based simulated reasoning.
- **Independent of `//think_text`:** The legacy `//think_text keep/remove` setting does not control native Gemini thoughts.
- **Clean output:** Thought summaries are kept separate from the regular response and only included when Gemini actually returns them.

### Tested Models

The following models have been successfully tested:

- Gemini 3.5 Flash-Lite
- Gemini 3.6 Flash

Gemini 3.7 Flash support is not yet confirmed because the Google API has repeatedly returned `503 UNAVAILABLE` errors due to high demand.

### Important Notes

- Gemini returns thought summaries, not necessarily its complete internal reasoning.
- Thought availability and content depend on the selected model and Google's API response.
- This fork focuses on direct Google Gemini API integration.
- The original OpenRouter provider has not been modified.

## Running locally

To run GeminiForJanitors on your desktop computer or on your phone, you need three things:

- `uv` with Python 3.13 or greater installed.
- A program that can generate tunnel URLs for your proxy, such as `cloudflared` or `localtunnel`.
- A copy of GeminiForJanitors' source code, which you can get through `git` or by manually downloading and unzipping the source from GitHub.

To run the proxy locally, you should know how to use the command line, such as `cmd.exe` or `powershell.exe`/`pwsh.exe` on Windows, or the terminal on Linux/MacOS, or Termux on Android.

### Installing `uv` and Python

Go to https://docs.astral.sh/uv/getting-started/installation/ and follow the guide for your operating system. In the case of Termux, you should instead run:

```bash
pkg install -y uv python

After that, you should then be able to run "uv" from the command line.

Next, run this command and take note of what Python version(s) you have installed:

uv python list

If you don't have any Python version installed, run this command:

uv python install 3.13

Installing a Tunneling Program

To use the proxy from outside your local network, you need a program that can tunnel external connections into your device for the proxy to handle. Programs such as "cloudflared" or "localtunnel" can do this, as well as many others. GeminiForJanitors has special support for "cloudflared", but any tunneling program that you can run on your device should work just fine.

To use "cloudflared", go to https://github.com/cloudflare/cloudflared/releases/ and download the appropriate executable for your operating system. In the case of Termux, you should instead run:

pkg install -y cloudflared

Take note of the location where you downloaded the executable, e.g. "C:\Users\YourName\Downloads\cloudflared-windows-amd64.exe". To get the location on Termux, you can run "type cloudflared" which should give you something like this:

cloudflared is hashed (/data/data/com.termux/files/usr/bin/cloudflared)

In the case of other tunneling programs, you might have to open two separate command lines: one for running GeminiForJanitors, and one for running the tunnel. The exact commands depend on the program. With "localtunnel", for example, you need to install NodeJS and "npm", then run:

npm install -g localtunnel

Then on the second command line run:

lt --port 5000

After starting GeminiForJanitors.

Downloading GeminiForJanitors

If you have "git" installed on your command line, you can run the following command:

git clone --depth=1 https://github.com/leerek97-cell/GeminiForJanitors.git

This will download a copy of this fork on your device, and you can update this copy by running "git pull" inside its folder.

Alternatively, you can open this link to download a copy:

https://github.com/leerek97-cell/GeminiForJanitors/archive/refs/heads/master.zip

This is a zip file from which you can extract a folder with GeminiForJanitors' source code. This copy cannot be updated without downloading a new one.

Running GeminiForJanitors

Make sure your command line's current working directory is within your copy's folder.

By default, GeminiForJanitors expects to have a Redis database. This is not necessary for running locally, so to disable this, you need to run the following command depending on your operating system:

# if you are on Linux/MacOS/Termux
export GFJPROXY_DEVELOPMENT=y

:: if you are on Windows using cmd.exe
set GFJPROXY_DEVELOPMENT=y

# if you are using powershell.exe/pwsh.exe
$env:GFJPROXY_DEVELOPMENT = 'y'

If you are using "cloudflared", you need to set "GFJPROXY_CLOUDFLARED" to the location of the executable, as follow:

# if you are on Linux/MacOS/Termux
export GFJPROXY_CLOUDFLARED='/data/data/com.termux/files/usr/bin/cloudflared'

:: if you are on Windows using cmd.exe
set GFJPROXY_CLOUDFLARED=C:\Users\YourName\Downloads\cloudflared-windows-amd64.exe

# if you are using powershell.exe/pwsh.exe
$env:GFJPROXY_CLOUDFLARED = 'C:\Users\YourName\Downloads\cloudflared-windows-amd64.exe'

After that, you are ready to run GeminiForJanitors. On Termux, you might have issues running the proxy since your installed Python version might not be 3.13; in this case, make sure to include the "--python 3.13" part, and change "3.13" to whichever version you have installed. If you have Python 3.13 installed, you can omit it.

uv run --python 3.13 --no-dev flask --app "gfjproxy.app:create_app()" run -h 127.0.0.1 -p 5000

Adaptive Cooldown

It is possible to make the proxy apply a cooldown only if the bandwidth usage is above a given value by configuring the "GFJPROXY_COOLDOWN" value. For example, consider the following cooldown policy:

- Apply a 30-seconds cooldown by default.
- Apply a 60-seconds cooldown if bandwidth usage is above 70 GB.
- Apply a 90-seconds cooldown if bandwidth usage is above 80 GB.

To set up such a policy, set "GFJPROXY_COOLDOWN" to:

30, 60:70, 90:80

Then deploy your instance. You can read the logs for "Using cooldown policy" to see if your changes have been applied.
